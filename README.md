# КП «Тихое»

Промосайт строящегося посёлка у озера Врево: Next.js 16, React, TypeScript, Prisma 6 и постоянная SQLite через `@prisma/adapter-libsql`. Название, контакты, тексты, инфраструктура, маршруты, фотографии, строительство и коммерческие данные редактируются через `/admin` без пересборки.

## Быстрый старт

Node.js 24 (подойдёт Node 22.13+), npm, Linux с постоянным диском. Все команды выполняются из корня репозитория, в этой среде — `/workspace/vrevo`.

```bash
export npm_config_cache=/workspace/.npm-cache
export CHECKPOINT_DISABLE=1
export NEXT_TELEMETRY_DISABLED=1
npm ci
# Копировать только при отсутствии своей конфигурации:
test -f .env || cp .env.example .env
mkdir -p storage
npm run db:generate
npm run db:push
npm run db:seed
npm run admin:init
npm run dev
```

В текущей среде эти шаги выполнены. `db:seed` повторяем: он не перезаписывает изменения менеджера. `db:push` не запускает автоматический сброс данных; для изменения схемы рабочей базы сначала сделайте резервную копию. JavaScript Schema Engine включён через `prisma.config.ts`; дополнительное скачивание движков с `binaries.prisma.sh` не требуется. Флаг адаптера CLI в Prisma 6 экспериментальный, версии зафиксированы и проверены вместе. Не обновляйте Prisma отдельно от адаптера.

Для production-сборки: `npm run build`, затем `npm start`. Отдельно запускается `npm run mail:worker`. Процессы должны перезапускаться после восстановления среды; диск, база и загрузки сохраняются. Используйте существующий checkout; отдельный Git worktree не нужен.

## Администратор

`npm run admin:init` создаёт только отсутствующую учётную запись для локальной демонстрации со случайным паролем. Временный пароль хранится **только** в игнорируемом файле `storage/local-admin-password` с правами 600. Откройте этот файл локально для входа; не отправляйте его в Git, чат или логи. `/admin` не включён в публичное меню. При повторном init существующая учётная запись сохраняется.

Перед публичным запуском замените пароль (не менее 14 символов). Например, в Bash:

```bash
read -rsp 'Новый пароль администратора: ' VREVO_ADMIN_PASSWORD
ADMIN_PASSWORD="$VREVO_ADMIN_PASSWORD" npm run admin:create
unset VREVO_ADMIN_PASSWORD
```

Команда сохраняет scrypt-хеш, снимает признак временной учётной записи и отзывает сессии. После успешной смены удалите локальный файл временного пароля. Постоянный пароль не сохраняйте в файлах проекта. Сессии — случайные серверные токены, в БД хранится их SHA-256; cookie HttpOnly, SameSite=Strict, Secure на production. Локальное HTTP-тестирование production-сборки допускается только с `ALLOW_INSECURE_LOCAL_COOKIE=1`; на публичном сервере эту переменную не задавать. Запросы изменения проверяют Origin; попытки входа ограничены.

## Данные и схема участков

- `prisma/schema.prisma` — база, участки, контент, медиа, записи строительства, заявки, сессии и результаты уведомлений.
- `data/geometry.json` — отдельные контуры и стабильные технические ID, координатное поле 878×1041. Коммерческие данные в геометрии не хранятся.
- `public/plan/genplan.webp` и `materials/genplan.pdf` — растровая подложка и исходник. Границы извлечены из реальных растровых подразделений, а не из сетки; два слабоконтрастных контура 33 и 35 обведены вручную по соседним границам. Подложка сохраняет исходные дороги, берег и обозначения планируемых объектов. Перед публикацией нужна сверка точности владельцем.
- На исходнике **дважды 134**: `plot-134-east` и `plot-134-west`. Между 126 и 128 нет однозначно читаемого 127. Номера не исправлялись по догадке. 146 оцифрованных контуров — технический результат обработки, не подтверждённое рекламное число участков.
- Мелкая таблица площадей требует сверки; начальные площади, индивидуальные цены и кадастровые номера оставлены `null`. Общая цена предложения от 90 000 ₽/сот. не применяется ко всем участкам автоматически.
- Проданы **только 68–72 и 99–103**, ровно 10 участков. Другие распознанные контуры первоначально свободны. После редактирования повторное заполнение статусы не сбрасывает.
- Изменить номер/геометрию можно отдельной разработческой правкой после сверки; администратор редактирует статус, площадь, индивидуальную цену, кадастровый номер и описание. Публичная заявка никогда не меняет статус.
- Ссылка `?plot=17` открывает участок по номеру; `?plot=plot-17` — по стабильному ID. Для повторяющихся номеров используйте ID.

В `/admin`: выберите строку участка, измените поля, сохраните; соответствующий контур подсвечивается. Изменения видны в схеме, списке и карточке. Открытая публичная вкладка обновляет данные при возвращении фокуса и перед заявкой. Если статус изменился во время заполнения формы, сервер отклоняет недоступное действие. Фильтры по площади и цене появляются после внесения таких данных.

## Контент и фотографии

Первоначальные данные взяты из архива, документы сохранены в `materials/`. Получатели заявок не включены в публичный контент. Исходные изображения в `assets/photos/` не публикуются как статические файлы: `/media/[file]` проверяет доступность и статус прав, затем создаёт уменьшенную WebP-копию. Фотографии отложенно загружаются, кроме первого экрана; шрифты поставляются локально.

Галерея, подпись, категория, дата, порядок, автор, ссылка на источник, лицензия и публикационный статус редактируются в админке. Новые JPEG/PNG/WebP до 10 МБ проверяются и преобразуются сервером, затем сохраняются в `storage/uploads`. Непроверенные фотографии скрыты в `SITE_MODE=public`. При выборе свободной лицензии обязательно заполните авторство, источник и ссылку на лицензию. Оригиналы CC BY-SA сохранены, масштабирование/кадрирование веб-копии указано в подписи. Лицензия фотографии не распространяется на код сайта.

P01 показывает берег Врево у другого комплекса, а не готовый пляж этого проекта. Череменецкое озеро подписано своим именем; леса Шалово-Перечицкого заказника не выдаются за территорию посёлка. 13 снимков требуют подтверждения прав. Собственные фотографии стройки пока не предоставлены, поэтому начальная лента строительства скрыта. Новые записи создаются через вкладку «Ход строительства», имеют дату, текст, фото и флаг публикации. Удаление связанного фото запрещено до удаления записи.

## Заявки и почта

По умолчанию `SITE_MODE=demo`: форма явно предупреждает о тестовом режиме, сохраняет обращение с `demo=true`, **не отправляет письма**, не обещает звонок менеджера или бронь. Используйте тестовые персональные данные. Политика и согласие в этом режиме явно обозначены как демонстрационные.

Для публичного приёма задайте в защищённой конфигурации сервера:

- `SITE_MODE=public`, `SITE_URL=https://ваш-домен`.
- `DATABASE_URL=file:/абсолютный/постоянный/путь/dev.db` (по умолчанию `file:./storage/dev.db`, относительно корня процесса).
- `LEAD_RECIPIENTS=d@popov.tel,tichvlad@mail.ru` — серверная настройка, не публичные контакты.
- `SMTP_HOST`, `SMTP_PORT` (обычно 587 или 465), `SMTP_SECURE` (`true` для TLS на 465), `SMTP_FROM`.
- Если провайдер требует: `SMTP_USER`, `SMTP_PASSWORD`. Они остаются на сервере. TLS-проверка включена; не используйте отключение проверки сертификатов.

Для SMTP нужен прямой исходящий доступ к SMTP-серверу на соответствующем порту. HTTPS-прокси для API-ключей не заменяет SMTP TCP. До выбора провайдера домены и реальные реквизиты не выдумывались. Настройки SMTP проверяйте с тестовым получателем, не отправляйте фиктивные заявки на рабочие почты.

Сначала заявка и **две независимые записи очереди** сохраняются одной транзакцией. Затем выполняется отправка. Успех формы означает надёжное принятие сервером, а не обещание доставки письма. Результат каждого получателя виден администратору. Временная ошибка не удаляет заявку; ручная кнопка повторяет только неуспешные письма. `requestKey` исключает дубликаты при повторе запроса. Сервер проверяет телефон, согласие, honeypot, участок и его актуальный статус; ограничения частоты сохраняются в БД.

`npm run mail:worker` обрабатывает очередь раз в минуту и делает до пяти автоматических попыток, затем нужна проверка менеджером. Для ручного прохода: `npm run mail:retry`. При сбое процесса в момент SMTP-ответа запись может остаться `sending`: сначала проверьте журнал SMTP-провайдера по Message-ID, затем разработчик может перевести подтверждённо неотправленную запись в `failed`. Это исключает слепую автоматическую повторную рассылку; абсолютная гарантия exactly-once через SMTP невозможна.

## Проверки

```bash
npm run typecheck
npm run lint
npm run build
npm test
npm run test:e2e
npm run check:publish
```

`check:publish` сейчас намеренно возвращает ненулевой код: внешние материалы ещё не готовы. Unit/integration-тесты используют отдельную `storage/unit-test.db`, локальный SMTP-приёмник на 2526 и адреса `example.test`; настоящие получатели в тестах не используются. Playwright использует отдельную `storage/e2e-test.db`, случайную тестовую учётную запись, production-сервер на 3100 и Chromium. В этой облачной среде Chromium установлен в `/usr/bin/chromium`; на другой машине задайте `CHROMIUM_PATH` или установите браузер через Playwright в доступный каталог и укажите путь. Перед E2E нужна актуальная сборка.

Покрываются: десять исходных проданных участков, уникальные ID, неизменность данных после повторного seed и нового подключения, серверная валидация, частичный SMTP-сбой и повтор, ссылки на участки, три статуса, передача plotId в заявку, запрет брони проданного, идемпотентность, запрет анонимного изменения и чужого Origin, админское изменение, загрузка фото и записи, галерея с клавиатуры, отсутствие горизонтального переполнения на 360/390/768/1024/1440. Снимки проверок сохраняются в игнорируемом `storage/`.

## До публичного запуска

1. Владелец сверяет все границы/номера, повтор 134, пропуск 127 и таблицу площадей; после сверки отмечает это в админке «Перед публикацией».
2. Внести реальные реквизиты продавца, утверждённую политику и согласие. Заменить временный пароль.
3. Подтвердить рекламные права на фото P01 либо заменить его своим снимком Врево; неподтверждённые снимки выключить или подтвердить права. Статусы прав автоматически учитываются в публичном режиме.
4. Подключить SMTP и проверить настоящую доставку обоим получателям. Подтвердить постоянное хранилище, HTTPS-домен и резервное копирование.
5. Уточнить индивидуальные цены при необходимости, категорию земли и документы, условия пляжа, взносы, статус охраны и сроки сезона 2027. До подтверждения не обещаются ИЖС, асфальт, частный берег, бесплатное подключение или отсутствие взносов.
6. Проверить реальные маршруты от трёх городов и Луги. Сейчас ссылки ведут к подтверждённому въезду **58.584476, 29.856943 (широта, долгота)**, числовые расстояния и время не выдуманы. Региональная схема показывает направления, а не трассировку дорог. Не проверенный ориентир «10 минут от Луги» не утверждается как факт. Границы заказника относительно конкретных земель и реконструкция дорог требуют отдельной сверки.
7. Яндекс Метрика подготовлена и по умолчанию отключена. В админке задаются идентификатор и переключатель; скрипт загружается только после отдельного согласия посетителя. События: plots_open, plot_select, lead_start, lead_success, lead_error, phone_click, route_open; демонстрационный успех — отдельное demo_lead_success. Телефон, имя и комментарий в события не передаются, Вебвизор отключён. Реальный счётчик и согласованный владельцем порядок включения пока не предоставлены; внешняя доставка событий не проверялась.

Публичная форма блокируется, пока автоматическая проверка обнаруживает обязательные незаполненные настройки. Признак готовности не подтверждает юридическую точность материалов или фактическую доставку SMTP. Разработка и локальные проверки не публикуют сайт и не отправляют изменения в GitHub.

## Резервные копии и обновление

Постоянно храните `storage/dev.db`, `storage/uploads/` и исходные `assets/photos/`. Перед обновлением остановите web-процесс и mail-worker, затем создайте согласованную копию всей `storage/` в защищённое место вне публичного каталога (включая возможные `-wal` и `-shm` SQLite-файлы). Доступ к резервной копии ограничьте, потому что там телефоны заявителей. Резервные копии и загрузки нельзя коммитить. Восстановление: при остановленных процессах вернуть базу и uploads из одного комплекта, проверить права файлов и `DATABASE_URL`, затем запустить приложение и worker; проверить вход, участки и медиа. Для обновления зависимостей используйте lock-файл; сначала проверяйте изменения схемы на копии базы. Хостинг с эфемерным диском для этой конфигурации не подходит.
